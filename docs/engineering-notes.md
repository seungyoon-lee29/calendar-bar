# 구현 주의점

America/Asuncion의 2023년 10월 1일은 00:00이 없고 01:00부터 시작한다. 월 시작에 날짜를 더하기만 하면 이후 셀과 조회 종료까지 01:00이 전파됐다. 각 날짜를 startOfDay로 정규화해야 표시 기간 밖 첫 한 시간을 조회하지 않는다. 회귀 테스트가 이 경우를 재현한다.

Swift Package 실행 파일의 최상위 코드는 현재 언어 설정에서 main actor로 간주되지 않는다. main-actor 앱 delegate 초기화는 명시적 main actor 문맥에 두며 NSApplication.run 동안 delegate를 보관한다.

메뉴막대 전용 앱은 일반 창이 없으면 컴퓨터 사용 도구의 앱 선택이 timeoutReached로 끝날 수 있다. 임시 검증 창을 넣어 UI를 확인한 뒤 최종 빌드에서 제거했다. 실제 메뉴막대 아이콘을 눌러 열린 팝오버를 확인해야 한다.

터미널에서 앱 바이너리를 직접 실행하면 캘린더 권한의 책임 프로세스가 실행 도구로 귀속될 수 있다. 실제 계정 검증은 Finder에서 앱 번들을 열어 진행한다. ad-hoc 재서명 뒤에는 기존 캘린더 접근이 유지된다고 가정하지 않는다.

이 맥에서는 첫 개발 실행으로 CalendarBar가 Orca의 메뉴막대 표시 목록에 묶였다. 상태 버튼 창이 (0,-22,38,22), screen=nil인 채 생성되어 원래 구현은 화면 좌하단에 팝오버를 열었다. 현재는 유효한 화면 좌표가 있을 때만 연다. 시스템 설정의 메뉴막대에서 Orca 표시를 켜니 CalendarBar 개별 항목도 생성되었다. Orca를 다시 끄면 CalendarBar도 blocked host가 되는 현상을 시스템 로그로 확인했으므로 현재 둘 다 켜 둔 상태다. 다른 표시 설정을 초기화하지 않았다.

드래그 종료 시 월 데이터만 교체하면 달력이 순간적으로 바뀐다. 시각적인 이동량과 실제 선택 월을 분리하고 애니메이션 완료 시점에 한 번만 월을 변경한다. 다시 열거나 다른 날짜로 이동하면 이전 전환의 완료 콜백을 무효화한다. 페이지의 날짜·일정 데이터가 같으면 날짜 버튼과 점을 다시 그리지 않아 드래그 중 반복 포매터 생성을 줄인다.


조회 채널 무효화 때 전역 세대만 올리면 진행 중이던 다른 범위가 영구 로딩으로 남거나 이전 응답이 새 결과를 덮을 수 있다. 범위 없는 직접 발생분 확인도 권한과 캘린더 선택을 다시 확인해야 한다. 채널·요청 세대·권한 변경의 교차 순서를 가짜 backend 회귀 테스트로 고정했다.

알림의 조회 실패는 삭제가 아니다. 다만 명시적 끄기·숨기기·개인정보 정리와 손상된 설정의 안전한 취소는 실패와 독립적이어야 한다. 반복 하나의 모호함이 다른 발생분 예약까지 취소하지 않도록 발생 기준별로 격리하고 전달된 알림도 따로 확인한다.

알림 타이머의 기본 `Task.sleep(for:)`를 취소·재설정할 때 `swift_task_dealloc`의 SIGABRT를 재현했다. nanoseconds 오버로드로 바꾼 뒤 100회 재설정·취소와 weak 해제 회귀 테스트가 통과했다. Swift 런타임 내부 원인은 확정하지 않았다.

실제 EventKit의 분리된 반복 발생분은 삭제와 멀리 이동함을 단일 범위로 판별할 수 없다. 직접 확인의 범위 밖 결과를 삭제로 취급하지 않고 확실한 시리즈 키만 연결 근거로 쓰며 나머지는 확인 필요로 남긴다. 실제 계정의 취소·분리·원거리 이동 조합은 별도 검증이 필요하다.

이 실행 환경에서 종료한 자식의 그룹을 `os.killpg(group, 0)`로 확인하면 ESRCH 대신 EPERM이 발생했다. `/bin/sleep`의 제한 실행으로 재현했다. EPERM은 무시하지 않고 별도 `ps` 목록에 그 그룹의 구성원이 없는 경우에만 종료로 판정한다. 구성원이 있거나 목록 조회가 실패하면 정리 실패를 보고한다. SIGTERM을 무시하는 손자까지 제거하고 그룹 부재를 확인하는 실제 프로세스 테스트를 유지한다.


예정 목록에서 `LazyVStack` 아래 날짜별 `ForEach`가 여러날 발생분의 같은 ID를 여러 번 펼치면 다음 날짜의 행이 빈 공간으로 사라졌다. 합성 일정의 9/28 행은 보이지만 9/29의 두 행은 AX에도 없고 렌더도 비어 있었다. 날짜와 발생분을 합친 행 ID로 바꾼 뒤 두 날짜 모두 제목·종 버튼이 나타나는 것을 실제 팝오버에서 확인했다. 데이터 계산 테스트만으로 발견하지 못했던 렌더 문제다.

컴퓨터 사용 도구가 비활성 QA 창의 이전 요소를 반환할 수 있다. 일반 창의 Raise 뒤 최신 상태를 읽고, 인덱스가 무효하면 현재 화면을 다시 확인해야 한다. 접근성 트리만 남아 있는 닫힌 팝오버를 열린 화면으로 판정하지 않는다.
