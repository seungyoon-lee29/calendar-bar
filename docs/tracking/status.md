# 구현 현황

월간 달력·오늘 강조·날짜 선택·월 이동과 드래그, 선택일 목록, 읽기 전용 시스템 캘린더 연결, 표시 캘린더 선택, 로그인 항목 관리가 코드에 구현되어 있다. 최신 소스와 확장된 정리 테스트를 합친 프로젝트 루트에서 `python3 scripts/verify.py` 종료 0을 확인했다. Swift 108개·프로세스 정리 5개와 release 번들·서명 검증이 모두 통과했다.

실제 메뉴막대 기준 팝오버 렌더, 좌우 드래그·같은 일자 유지·짧은 드래그 제외, Escape 닫기와 재열기 오늘 복귀를 확인했다. 이전 빌드에서 Google 기본 캘린더 9/29 일정 2개의 제목·시간을 읽었고 Apple 캘린더의 동일 날짜와 일치함을 확인했다. 재실행 시 권한·캘린더 선택 복원과 실제 로그인 실행 등록 enabled까지 확인했다. 바깥 클릭으로 닫히는 동작은 사용자가 최종 확인했다. 실제 재로그인 확인은 수행하지 않았다.

현재 제품 범위에는 선택 캘린더 제목 검색, 날짜별 예정 일정, 사용자가 켠 일정의 복수 로컬 알림이 포함된다. 일정 편집·공휴일 전용 데이터·음력·다른 운영체제는 포함하지 않는다. 기존 소스의 공개 게시 결정과 별개로 이번 변경의 push·배포는 수행하지 않았다.

월 이동은 드래그 중 손을 따라 움직이고 전환 후 선택 월을 확정하도록 개선했다. 짧은 드래그 복귀·중복 전환 방지 테스트를 추가했으며 사용자가 설치본의 부드러운 전환을 직접 확인했다.


검색 기본 앞뒤 1년·기간 편집·역전 오류·0건·선택 캘린더 필터·결과 날짜 이동과 강조를 합성 QA 실제 화면에서 확인했다. 4/5/6주 달력, 예정 기간 30일 추가, 여러날 행, 긴 제목과 종 버튼을 확인했다. 여러날 행이 다음 날짜에서 사라지는 렌더 결함은 수정 후 재검증했다.

시간/종일 복수 입력·추가·삭제·기본값 복사와 비소급·반복 앞으로/이번 발생 예외·예외 해제·끄기·내용 숨김·권한 오류 표시는 실제 UI에서 확인했다. 시스템 설정에서 독립 QA 앱 알림만 허용한 후 시스템 대기 요청 재조회에 근거한 실제 예약 2개 표시와 트리거 전 앱 종료를 확인했다. 2026-09-28 사용자가 “알람보여”라고 응답해 실제 시험 알림 표시를 수동 확인했다. 도구의 배너 관찰·전달 목록 확인과는 구별하며, 콜드·웜 알림 클릭 후 목적 날짜·행 강조는 아직 사용자 확인 대기라 기능 전체를 완료로 판정하지 않는다. 실제 계정의 반복 분리·취소·멀리 이동 조합과 재로그인은 미검증이다.

사용자 수동 클릭 확인을 위해 Calendar Bar Runtime QA의 알림 허용은 현재 켜 둔 상태이고 OS 알림 정리를 보류했다. 앞선 검증 종료 시 QA 앱과 시험 watchdog을 종료했고 원래 설치본을 유지했다. 이후 사용자의 클릭 확인 중에는 GUI 조작·QA 정리·권한 복원을 수행하지 않는다. 확인 후 해당 QA 규칙·알림을 정리하고 원래 꺼짐 상태로 복원해야 한다.
