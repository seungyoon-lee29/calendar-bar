# 시스템 연동 계약

외부 HTTP API는 없다. EventKit의 fullAccess만 일정 조회 허용으로 간주한다. notDetermined는 미요청, denied/writeOnly는 연결 거절 상태, restricted는 제한 상태다. 권한 부족을 정상 0건 결과로 변환하지 않는다.

조회는 달력 격자·검색·예정 일정·알림 각 채널의 시작 포함·종료 제외 날짜 범위와 선택 캘린더 ID 집합을 받는다. 빈 선택으로 전체 캘린더를 조회하지 않는다. 캘린더는 시스템 ID·이름·출처·색을 전달하고, 일정은 캘린더 ID·이벤트 ID·발생 시작·종료·제목·종일 여부를 전달한다. 동일 이벤트 ID의 반복 발생분을 합치지 않는다.

화면 상태는 연결 필요, 캘린더 없음, 선택 필요, 로딩, 조회 성공, 조회 실패로 구별한다. 성공은 0건을 포함한다. EventKit 변경 통지와 잠자기 복귀에 저장소를 다시 읽고 이전 객체를 재사용하지 않는다. 시스템 동기화 지연은 앱 외부 계약이다.

ServiceManagement의 enabled, notRegistered, requiresApproval, notFound를 각각 켜짐, 꺼짐, 승인 필요, 실패로 표시한다. 등록 요청을 보냈다는 사실만으로 켜짐이라 표시하지 않는다.

UserNotifications에는 앱 고유 접두사의 결정적 요청 ID, 알림 시각, 표시 내용, 내부 연결 토큰을 전달한다. OS의 예약 허용과 배너 표시 허용을 함께 확인하고 대기 요청 재조회로 실제 예약을 판정한다. 저장 오류·권한 필요·부분 예약·확인 필요는 성공과 구별한다. 취소는 이 앱이 소유한 요청에 한정하며 정상 종료는 취소 요청이 아니다.

시스템 알림 응답의 토큰은 저장된 일정 식별 연결을 찾는 입력이다. 현재 선택·권한과 원래 발생 기준을 재검증한 뒤 목적 날짜를 연다. 사라짐·선택 밖·권한 부족·모호함·조회 실패를 각각 처리하고 이전 제목이나 payload 날짜만으로 개인 일정을 표시하지 않는다. 반복 발생분 조회 범위 밖은 삭제를 의미하지 않는다.
