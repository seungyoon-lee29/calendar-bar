- `Sources/CalendarBar/main.swift:26`의 `userNotificationCenter(_:didReceive:withCompletionHandler:)` 실제 알림 클릭 진입은 자동 라우터 테스트와 별개다. 두 합성 트리거 전에 앱을 종료했으나 컴퓨터 사용 도구가 알림 센터에서 날씨 위젯 창만 선택해 QA 배너·클릭을 직접 확인하지 못했다. 전역 공유/미러링 중 알림 정책은 꺼져 있었으나 다른 앱 개인정보에도 영향을 주므로 변경하지 않았다. 동일 ID의 원본 실행 파일 진단 복사본은 허용=2, 대기=0, 전달=0을 반환했지만 재빌드 코드 해시 차이도 있어 도착 증거로 사용하지 않는다. 2026-09-28 사용자가 “알람보여”라고 응답해 실제 시험 알림 표시는 수동 확인했다. 콜드·웜 실행의 실제 알림 클릭과 목적 날짜·행 강조는 아직 확인되지 않았다. 사용자 클릭 결과 확인 또는 같은 설치본으로 해당 경로를 다시 검증해야 하며, 확인 전 기능 전체를 완료로 표시하지 않는다.
- 실제 계정의 분리된 반복 발생분 취소와 원거리 이동을 구별하는 조합은 합성 테스트까지만 확인했다. `Sources/CalendarAccess/EventKitBackend.swift:64`의 직접 확인이 범위 밖일 때 삭제로 단정하지 않고 확인 필요로 남기지만, 계정 제공자별 반환을 보장하려면 사용자가 관리하는 원본의 읽기 전용 대조가 필요하다. 현재 검증은 원본 쓰기가 금지되어 이 조합을 임의 생성하지 않았다.

- 시험 알림을 누르면 알림만 사라지고 앱 화면이 열리지 않는다는 사용자 보고가 확인됐다. 2026-09-28 16:55 합성 예약 전에 QA 프로세스를 종료했고, 클릭 뒤 새 QA 프로세스가 생긴 것은 확인했다. 따라서 앱 실행 자체와 화면 표시·목적지 전달을 나누어 진단한다. `Sources/CalendarUI/CalendarAppCoordinator.swift:100`의 `openReminder(token:)` 표시 요청과 `Sources/CalendarBar/main.swift:34`의 `applicationShouldHandleReopen` 경로에 수명 회귀 검증을 추가했다. 이후 팝오버를 먼저 표시하고 활성화를 요청하는 수정 및 중복 QA 진단 번들 제거를 진행했으나 실제 클릭 결함이 해결됐다고 보고하지 않는다. 줄 번호는 이후 변경 때 이동할 수 있으므로 함수명으로도 확인한다. 기존 실제 클릭 미확인 항목은 이 결함 수정·재검증으로 해소해야 한다.
