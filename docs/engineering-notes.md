# 구현 주의점

America/Asuncion의 2023년 10월 1일은 00:00이 없고 01:00부터 시작한다. 월 시작에 날짜를 더하기만 하면 이후 셀과 조회 종료까지 01:00이 전파됐다. 각 날짜를 startOfDay로 정규화해야 표시 기간 밖 첫 한 시간을 조회하지 않는다. 회귀 테스트가 이 경우를 재현한다.

Swift Package 실행 파일의 최상위 코드는 현재 언어 설정에서 main actor로 간주되지 않는다. main-actor 앱 delegate 초기화는 명시적 main actor 문맥에 두며 NSApplication.run 동안 delegate를 보관한다.

메뉴막대 전용 앱은 일반 창이 없으면 컴퓨터 사용 도구의 앱 선택이 timeoutReached로 끝날 수 있다. 임시 검증 창을 넣어 UI를 확인한 뒤 최종 빌드에서 제거했다. 실제 메뉴막대 아이콘을 눌러 열린 팝오버를 확인해야 한다.

터미널에서 앱 바이너리를 직접 실행하면 캘린더 권한의 책임 프로세스가 실행 도구로 귀속될 수 있다. 실제 계정 검증은 Finder에서 앱 번들을 열어 진행한다. ad-hoc 재서명 뒤에는 기존 캘린더 접근이 유지된다고 가정하지 않는다.

이 맥에서는 첫 개발 실행으로 CalendarBar가 Orca의 메뉴막대 표시 목록에 묶였다. 상태 버튼 창이 (0,-22,38,22), screen=nil인 채 생성되어 원래 구현은 화면 좌하단에 팝오버를 열었다. 현재는 유효한 화면 좌표가 있을 때만 연다. 시스템 설정의 메뉴막대에서 Orca 표시를 켜니 CalendarBar 개별 항목도 생성되었다. Orca를 다시 끄면 CalendarBar도 blocked host가 되는 현상을 시스템 로그로 확인했으므로 현재 둘 다 켜 둔 상태다. 다른 표시 설정을 초기화하지 않았다.
